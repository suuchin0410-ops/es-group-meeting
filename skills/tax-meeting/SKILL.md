# esグループ月次会議フロー

3社の財務データを分析し、月次会議を経て、AIフィードバックで改善サイクルを回す対話型ワークフロー。

## 月次サイクルの全体像

```
┌─────────────────────────────────────────────────────────────┐
│                    月次サイクル                                │
│                                                               │
│  Phase 1          Phase 2          Phase 3         Phase 4    │
│  データ更新  ──→  会議実施  ──→  議事録作成  ──→  AIフィードバック │
│  (ダッシュボード)   (人間作業)       (Notion)        (分析・提案)   │
│       ↑                                                  │    │
│       └──────────── 翌月、前回FBをもとに議論 ─────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

## 対象3法人

| 法人 | 事業 | 決算月 | ファイル |
|------|------|--------|----------|
| ㈱esエンターテイメント | 飲食業（恵愛・村・弁当・シェア・サウナ） | 6月（期首7月） | 月次報告-YYYYMM.xlsx |
| ㈱エスクリエイト | コンサルティング | 6月（期首7月） | SC-月次検証-YYYYMM.xlsx |
| ㈱esライフワーク | 就労継続支援A型/B型 | 3月（期首4月） | LW-月次検証-YYYYMM.xlsx |

## 共通ルール

- **設定ファイル:** `app/config/companies.yaml` を参照して法人情報・シート名を把握する
- **ダッシュボード:** `app/dashboard.py` — Streamlitで3社の財務データを可視化
- **Notion（旧ワークスペース）:** `app/notion_writer.py` / `app/notion_reader.py` — トークンは `app/config/.notion_token`
- **Notion（esグループ会議）:** 別ワークスペース。トークンは `app/config/.notion_token_es_group`
  - 親ページID: `3808a77d-6ccc-808e-b17c-e0bf93ac67e6`
- **全フェーズ完了時に、NotionページURLとダッシュボードURLを必ず提示する**
- **前月のAIフィードバック（Phase 4の成果物）を次月のPhase 1・2で参照し、改善サイクルを回す**

## 途中参加の判定

ユーザーの発話から、どのフェーズから開始するか判定する:
- 「esグループ」「月次会議」「esMTG」「データを更新」→ Phase 1 から開始
- 「会議やります」「ミーティング」→ Phase 2 から（ダッシュボードが最新か確認後）
- 「議事録をアップした」「議事録」「Notionに貼った」→ Phase 3 から
- 「フィードバック」「分析して」「AI分析」→ Phase 4 から
- NotionのURLが添えられている場合 → そのページを対象にPhase 3 or 4

## Phase 1: データ更新・ダッシュボード反映

毎月の月次データ（Excel）をもとに、ダッシュボードを最新状態にアップデートする。

### 前提

- ユーザーが3社の月次Excelを `data/monthly/` に配置済み
- ファイル命名規則: `{prefix}-YYYYMM.xlsx`（companies.yaml参照）

### 手順

1. `data/monthly/` のファイル一覧を確認し、各社の最新月次データを特定
   - 最新ファイルの月が前月以前 → 警告:「{法人名}の最新データは{YYYY年MM月}分です。新しいデータはありますか？」
2. `app/dashboard.py` のデータ読み込みロジックで3社のExcelを処理:
   - BS千円シート → BS推移（流動資産・固定資産・流動負債・固定負債・純資産 + 詳細項目）
   - PL推移シート → PL推移（売上高・売上原価・粗利・販管費・営業利益）
   - CF推移シート → CF推移（営業CF・投資CF・財務CF・現金増減）
   - セグメント別（esエンタのみ: 恵愛・村・弁当・シェア・サウナ）
   - PL予実対比シート → 予算vs実績
   - 収支計画シート → 計画値
3. ダッシュボードをローカルで起動して動作確認:
   ```
   cd app && streamlit run dashboard.py
   ```
4. 前月のAIフィードバック（Phase 4で生成）があれば読み込み、改善の進捗を確認:
   - Notionの「esグループ会議」ワークスペースから直近のフィードバックページを取得
   - 前回提案のうち、数値に反映されている改善/悪化を特定
5. データの整合性チェック:
   - BS: 資産合計 = 負債合計 + 純資産合計（各月で検証）
   - CF: 期首現金 + 現金増減 ≒ 期末現金
   - PL: 売上 - 原価 = 粗利（許容誤差1千円）
6. 確認結果をユーザーに報告

### 完了条件
- ダッシュボードが最新データで正常に動作している
- データ整合性チェックが全てパス
- 「Phase 1 完了。ダッシュボードを最新データに更新しました。『次へ』で会議の準備に進みます」

## Phase 2: 会議実施（人間作業）

税理士・経営者が最新ダッシュボードを見ながら月次会議を行う。Claude側の作業はない。

### 表示するメッセージ

```
esグループ月次会議を実施してください。

ダッシュボード: [ローカル起動中のURL or デプロイURL]

参考資料:
- 前回AIフィードバック: [NotionページURL]（あれば）
- 各社の注目ポイント:
  * esエンターテイメント: [Phase 1で特定した注目事項]
  * エスクリエイト: [同上]
  * ライフワーク: [同上]

会議終了後:
1. 文字起こしテキストをNotionの「esグループ会議」ワークスペースにアップ
2. 「議事録をアップした」と言ってください（NotionページURLも添えてください）
```

### 待機条件
- ユーザーが「次へ」「議事録をアップした」等と言うまで何もしない

## Phase 3: 議事録の作成・Notion書き込み

ユーザーがNotionにアップした議事録（文字起こし or メモ）を構造化する。

### 手順

1. ユーザーからNotionページのURLまたはIDを受け取る
   - 「esグループ会議」ワークスペースのトークン（`app/config/.notion_token_es_group`）を使用
2. Notion APIで議事録テキストを取得
3. 名前マッピングを適用（`companies.yaml` の `name_mapping` 参照）:
   - 池田/いけだ/先生 → 池田（税理士）
   - 椎名/しいな → 慎也（経営者）
4. テキストを法人別・議題別に構造化
5. 構造化議事録をNotionページに書き込み（既存内容を上書き）

### 構造化議事録のテンプレート

```

参加者 / 所要時間

---

### esエンターテイメント

  - FL比率、人件費、仕入れに関する議題

### エスクリエイト
  - 売上・販管費に関する議題

### esライフワーク
```

- 「Phase 3 完了。決定事項・アクションアイテム:」のあとに主要決定事項を列挙

## Phase 4: AIフィードバック

議事録の内容 × ダッシュボードの3社財務データを突き合わせ、次回会議に向けたAIフィードバックを生成する。

### 手順

1. Phase 3で作成した構造化議事録を読み込み
2. ダッシュボードと同じデータソース（3社Excel）から最新の財務指標を取得:
   - BS: 流動資産・現金預金・流動負債・純資産の推移
   - PL: 売上・原価率・粗利率・営業利益の推移
   - CF: 営業CF・現金増減の推移
   - セグメント別売上（esエンタのみ）
   - 予実対比（あれば）
3. 前月のAIフィードバックがあれば読み込み、提案の実行状況を追跡
4. 以下の観点で総合分析を行う

### 分析の観点

**a. 3社連結サマリー**
- 連結売上高・営業利益・現金預金・純資産のテーブル
- 前月比の変動を明示

**b. 法人別ヘルスチェック**
各法人について、議事録の議論内容 × 財務データを突き合わせ:
- esエンターテイメント: FL比率、セグメント別収益性、計画比乖離、原価管理
- エスクリエイト: 売上安定性、利益率、キャッシュポジション、成長余地
- ライフワーク: 国保連収入変動、人件費比率、利用者数、補助事業費

**c. 重要課題と議論ポイント**
会議で議論された内容から、表面的な症状ではなく根本原因を特定する。
未解決事項・結論が出なかった議題を明示し、次回までのアクションを提案する。

**d. クロスカンパニーの視点**
- 法人間の資金移動・取引の整理状況
- グループとしての税務戦略（簡易課税、役員報酬等）
- 事業間シナジーの可能性

**e. 前回フィードバックの追跡**（2ヶ月目以降）
前回Phase 4で出した提案について:
- 実行されたもの → 効果の検証
- 未着手のもの → リマインドまたは取り下げ判断

**f. 次回会議の優先アジェンダ**
優先度付きのアジェンダテーブル（対象法人・所要時間目安付き）

**g. AI提案: 構造的な改善施策**
データと議論から導出される、中長期的な改善提案（2〜4件）

### 出力先

5. Notionの「esグループ会議」ワークスペースに**新規ページ**として作成:
   - ページタイトル: `YYYY-MM-DD AI分析フィードバック — esグループ月次会議`
   - アイコン: 🤖
   - 親ページ: `3808a77d-6ccc-808e-b17c-e0bf93ac67e6`

## 運用上の注意

- **月次サイクルの継続性**: Phase 4のフィードバックは必ずNotionに残し、翌月Phase 1で参照する。これがPDCAサイクルの起点になる
- **Notion APIの制限**: 1ブロック内のrich_textは2000文字まで。長いテキストは分割する
- **ブロック削除**: 一度に大量削除するとレート制限に当たる可能性がある。エラー時はリトライ
- **名前マッピング**: 新しい参加者が増えた場合、`companies.yaml` の `name_mapping` に追記する
- **トグルの活用**: 文字起こし等の長いテキストは必ずトグルに格納する
- **税務判断の注意**: AIフィードバックはあくまで整理・気づきの提供。税務上の判断は税理士に委ねる
- **データ整合性**: Phase 1で必ずBS/PL/CFの整合性チェックを実施する。不整合がある場合はユーザーに報告してからPhase 2に進む
